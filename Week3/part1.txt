I compared two platforms for improving conform.py with clean coding practices:
Claude Code running in the VSCode terminal (Claude Opus 5.5, high effort) and
GitHub Copilot Chat in VSCode agent mode (mai-code-1.1-flash). Both refactored
scripts printed exactly the same output as the original, which I confirmed by
running the original and the revised versions side by side. Both platforms
split the original pleaseConform function into small single-purpose functions
(such as find_intervals and a function that chooses which direction to flip),
removed the commented-out dead code, added docstrings and type hints, applied
PEP 8 formatting, and moved the entry point behind an
if __name__ == "__main__": guard. Claude Code went further: it renamed all
functions and variables to descriptive snake_case names (for example i became
position and start became run_start), replaced the bare 'F', 'B' and 'END'
strings with named constants, added an Interval type alias, flattened the
nested if in the one-pass version, and verified its own work by comparing the
outputs byte for byte and testing ten edge-case inputs. Copilot's changes were
similar in structure but lighter, and its summary was more general, without
named constants or self-testing. In terms of experience, Claude Code was more
thorough and explained every change, while Copilot was quick and convenient
because it works directly inside the editor. I also tried Google Antigravity
with a Gemini Flash model, but the agent repeatedly stopped with an
"Agent execution terminated due to error" message, so I could not complete a
refactor there; this showed me that the reliability of the platform matters as
much as the quality of the model.
